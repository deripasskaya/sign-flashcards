# План: контрольные тесты и сбор результатов по ученикам

> **Статус:** идея на будущее. К текущим флеш-карточкам по знакам не относится —
> они остаются как есть. Это отдельная фича («Контрольный тест»).

## Цель

Проводить контрольные тесты по дорожным знакам и получать **результаты по каждому
ученику**: кто, когда, сколько набрал, какие знаки завалил.

## Что НЕ входит

- Режим карточек (`index.html`) не меняем.
- Сбор результатов для карточек не делаем — он нужен только для тестов.

## Выбранные подходы

1. **Google Таблица + Apps Script** — основной канал. Результат уходит учителю
   автоматически, таблица сразу служит «дашбордом».
2. **Экспорт результата** — запасной канал. Если нет интернета или отправка не
   прошла, ученик скачивает файл/копирует код и присылает учителю.

Оба подхода совместимы и дополняют друг друга.

## Поток данных

```
Ученик ──► test.html ──┬──► Google Apps Script ──► Google Таблица (учитель)
                       └──► экспорт файла/кода (офлайн-резерв)
```

## Возможный формат теста

Отдельная страница `test.html` (или отдельный сайт):

1. Ученик указывает **ФИО + группу** (либо заходит по персональной ссылке).
2. Тест: N случайных знаков. Варианты заданий:
   - выбрать правильное название из 3–4 вариантов;
   - «знаю / не знаю» (самопроверка);
   - сопоставить картинку и текст.
3. Таймер (опционально).
4. Экран результата: балл, %, список ошибок, затраченное время.
5. Отправка в Google Sheets; при неудаче — предложить экспорт.

## Идентификация ученика (не решено)

| Вариант | Плюсы | Минусы |
|---|---|---|
| ФИО + группа (вводит сам) | Просто | Имя можно подделать |
| Персональные ссылки `?student=код` | Ученик не вводит имя вручную | Нужно раздать ссылки |
| Логин/пароль | Надёжно | Нужен бэкенд с аккаунтами |

Решение отложено. Для честного контроля предпочтительнее персональные ссылки или
логин/пароль.

## Какие данные собираем

- ФИО / код ученика, группа;
- дата и время (начало/окончание);
- число вопросов, правильных ответов, балл, %;
- **список неверно отвеченных знаков** (номера и названия) — самое полезное;
- затраченное время;
- версия набора знаков (сколько знаков было в базе).

## Что переиспользуем из текущего проекта

- `signs.js` — общая база знаков (372 записи);
- `icons/` — изображения знаков;
- `styles.css` — общий стиль;
- при желании — прогресс из `localStorage` (например, тест только по невыученным).

## Этапы внедрения

**MVP**
1. Страница `test.html`: выбор N знаков, простая выборка ответа, подсчёт балла.
2. Экран результата + кнопка «Скачать результат» (JSON/CSV).
3. Подключение Google Apps Script → запись строки в Google Sheets.

**Развитие**
4. Персональные ссылки или авторизация.
5. Панель учителя: список учеников, рейтинги, динамика по датам.
6. Разные наборы/уровни сложности, перемешивание вариантов ответов.

## Технические заметки

- **Apps Script**: функция `doPost(e)`, запись через
  `SpreadsheetApp.openById(...).getSheetByName(...).appendRow([...])`, развёртывание
  как Web App с доступом «Все».
- **Отправка из браузера**: Apps Script не отдаёт CORS-заголовки, поэтому запрос
  лучше слать как `fetch(url, { method: "POST", mode: "no-cors", body: new URLSearchParams(...) })`
  (form-urlencoded — чтобы не было preflight).
- **Экспорт**: формирование `Blob` (JSON/CSV) и скачивание через `URL.createObjectURL`.

## Приватность

Это персональные данные (ученики часто несовершеннолетние). Собирать минимум
(ФИО + группа, ничего лишнего), предупредить учеников, при необходимости оформить
согласие (152-ФЗ / внутренние правила школы).
